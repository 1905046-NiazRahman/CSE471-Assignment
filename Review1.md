# Gorilla: Large Language Model Connected with Massive APIs


>*This review of [this blog](https://mahirlabibdihan.github.io/CSE-471-ML-Assignment/) is written by [1905009 - Sidratul Muntaha Khan](https://github.com/Nahin009) | [1905010 - Md Muhaiminul Islam Nafi](https://github.com/nafiislam) | [1905046 - Niaz Rahman](https://github.com/1905046-NiazRahman) from CSE, BUET*


The blog post provides a good overview of the Gorilla system described in the research paper [Gorilla: Large Language Model Connected with Massive APIs](https://openreview.net/forum?id=tBRNC6YemY). It was fun to read. The authors explained most of the things in the designated paper. They introduced the model Gorilla and then explained its workings, suitability, and adaptability. Lastly, they depicted their own thoughts. But there were also negative comments that should be raised.


### Major Comments
1.  While the blog post highlights the strengths and potential of Gorilla, it doesn't address its limitations. For instance, the paper acknowledges that the current implementation is limited to machine learning APIs. Including a discussion of limitations would provide a more balanced perspective.

2. The blog post could benefit from visualizations to better illustrate key concepts. For example, a diagram depicting the architecture of Gorilla and the flow of information during training and inference would enhance understanding. The paper includes several figures that could be adapted for the blog post

3. The blog post briefly mentions potential applications of Gorilla, such as automated software development, dynamic knowledge systems, and educational tools. It could be more insightful to delve deeper into these applications, providing specific examples of how Gorilla could be used in each domain.

4. From the blog, it was not clear that Gorilla works by combining both instruction and API pair where instruction is provided by the user and API is generated by the retriever that uses Retriever-Aware training (RAT). Mentioning it clearly beforehand would have made the blog clearer and easier to understand. For example, explaining Figure 2 could have done the trick.

5. References or full forms should have been added when using keywords or jargon for example “AST-based”.

6. Comparisons with the existing methods provided in Tables 1-5 of the designated paper should have been added briefly or mentioned shortly to illustrate Gorilla's robustness and superior performance.


### Minor Comments
1. The paper “Gorilla: Large Language Model Connected with Massive APIs” should have been cited with due reference or the mention of NeurIPS 2024 would have been better in the introduction section. It would have made the blog intro more compact.

2. Grammatical mistakes should have been taken care of. For example, “is to tuned” should be “is to tune”.

3. The blog post briefly mentions future directions for Gorilla. Expanding on these directions and discussing potential research avenues would provide valuable insights into the future of LLMs and API interaction.

4. The figures should have captions that properly describe the things within them.The figures do not have the citations from where it was taken. This should be added.

5. Tables could have been added to make the deductions seem more factual.

6. Including snippets of code demonstrating how to use Gorilla would make the blog post more practical and engaging for developers. The paper mentions that Gorilla's code is available. Linking to the code repository or showcasing a simple example would be helpful.
